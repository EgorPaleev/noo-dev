# NooRules Dev

**Рабочий процесс для разработки с Codex и Claude Code.** Подключите NooRules к репозиторию и опишите задачу обычным сообщением. Агент разберётся в правилах проекта, предложит план с проверками и после вашего «запускай» проведёт задачу от рабочей ветки до готового diff.

NooRules пригодится, если вы хотите заранее понимать, что изменится, видеть ход работы и получать результат с проверками, принятыми в вашей команде.

## Что входит

- **Подключение проекта.** Агент находит инструкции, команды запуска и проверок и собирает карту репозитория для следующих задач.
- **Навыки разработки.** Уточнение требований, подготовка ветки, реализация, тестирование, ревью, подготовка коммита и выпуска.
- **Пайплайны.** Короткий маршрут для небольшой правки, отдельное ревью готового diff и многоэтапная работа с проверками и приёмкой.
- **База знаний.** Правила, шаблоны, примеры и чек-листы. Командные соглашения и команды проверок хранятся в вашем репозитории. [Каталог задач](plugins/noorules/assets/knowledge/task-index.md)

## Установка

Команды используют доступ к репозиторию GitHub по SSH.

### Codex

```sh
codex plugin marketplace add git@github.com:EgorPaleev/noo-dev.git
codex plugin add noorules@noorules-dev
```

Откройте репозиторий, в котором хотите работать, и вызовите `$noo-setup` в Codex.

### Claude Code

Выполните команды из репозитория, к которому хотите подключить плагин.

```sh
claude plugin marketplace add git@github.com:EgorPaleev/noo-dev.git
claude plugin install noorules@noorules-dev --scope project
```

Откройте Claude Code в этом репозитории и вызовите `/noorules:noo-setup`.

При первом использовании плагин напоминает обновить marketplace и пакет. `setup` создаёт только `.noorules/dev/rules.md` и блок входа для этого плагина. Повторный `setup` сохраняет существующие проектные файлы.

## Первая задача

После подключения откройте новую сессию в проекте. Рабочие навыки действуют только для подключённого проекта, в том числе при явном вызове. Можно начать с сообщения, лога, примера или готового diff. Существенные пробелы попадут в план, а доступную часть агент продолжит. Например:

> Исправь сообщение об ошибке входа. Проверь сценарий с неверным паролем.

1. **Согласуйте план.** Агент предложит имя и базу ветки, этапы работы и проверки. Для мелкой правки обычно достаточно ветки, изменения и целевой проверки. Если нужно отдельное ревью или подготовка коммита, добавьте их здесь.
2. **Напишите «запускай».** Агент пройдёт согласованные этапы без повторных подтверждений. В чате будет видно, когда он пишет код, запускает проверки или получает результаты от субагентов.
3. **Получите результат.** Агент покажет, что изменилось и какие проверки прошли. Если способ отправки ещё не согласован, он спросит, оставить ли работу локально, отправить ветку или открыть PR.

Пока задача открыта, по ID запуска можно запросить статус или продолжить работу в другом чате. Служебные файлы хранятся локально в `.noorules/runs/<id>/`. При закрытии NooRules удаляет их с помощью Python 3. Итоги остаются в чате, а нужные команде отчёты сохраняются отдельно. [Правила хранения](plugins/noorules/skills/noo-flow/references/state.md#завершение-и-очистка)
