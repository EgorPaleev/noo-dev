# NooRules Dev

NooRules Dev помогает собрать контекст для работы в репозитории и выстроить разработку, ревью, тестирование и выпуск. Плагин поставляет общие практики, шаблоны и материалы под поддерживаемые стеки. Документация, правила, команды и навыки конкретного проекта хранятся в его репозитории.

## Установка в Codex

```sh
codex plugin marketplace add git@github.com:EgorPaleev/noo-dev.git
codex plugin add noorules@noorules-dev
```

Откройте целевой репозиторий и вызовите `$noo-setup`.

## Установка в Claude Code

```sh
claude plugin marketplace add git@github.com:EgorPaleev/noo-dev.git
claude plugin install noorules@noorules-dev --scope project
```

Откройте целевой репозиторий и вызовите `/noorules:noo-setup`.

## Работа в подключённом проекте

1. При подключении NooRules покажет загруженную версию плагина и точку входа. По исходникам, конфигурации и существующим документам он соберёт карту проекта, команд и правил. Существенные пробелы предложит закрыть в целевом репозитории.
2. Откройте новую сессию в этом репозитории и отправьте задачу или ТЗ обычным сообщением. Можно явно вызвать рабочий навык, например `noo-review`. В обоих случаях агент учитывает инструкции и правила репозитория.
3. Агент покажет план и пайплайн вместе, даже для правки в одну строку. Для небольшой задачи предложит короткий вариант и согласует дополнительные шаги, например отдельное ревью или подготовку коммита. Обязательные проверки проекта входят в план. Если открытый вопрос меняет объём, агент сначала уточнит его.
4. Напишите «запускай», чтобы выполнить согласованные этапы без промежуточных подтверждений. При разработке `noo-branch` первым обновит удалённую базу и создаст рабочую ветку. Имя берётся из правил проекта, а при их отсутствии предлагается по типу задачи, например `fix/error-message`. База берётся из правил проекта или из основной ветки удалённого репозитория.
5. В чате агент показывает ID, текущую работу и задачи запущенных субагентов. По ID можно запросить статус или продолжить работу. Когда работа готова, агент сообщает результаты проверок и уточняет, оставить изменения локально, отправить ветку или открыть PR, если назначение ещё не согласовано.

Служебные файлы лежат в локально игнорируемом каталоге `.noorules/runs/<id>/`. При завершении запуска и при старте следующего агент сокращает завершённые записи до краткого итога с помощью Python 3. Обычные итоги хранятся до 30 дней, максимум 20 на проект. Записи активных задач и специально сохранённые материалы остаются доступны.

Для справочного вопроса или запроса только на план агент вернёт запрошенный ответ сразу.

Для отдельного ревью достаточно diff. Отчёт проверок учитывается, если он есть. Для спецификации по согласованному кейсу прототип используется при наличии.

Агент соблюдает обязательные правила проекта и сам выбирает технический подход в согласованных границах. Для задачи без готового маршрута он собирает этапы по ТЗ и фактическому устройству проекта.

Навыки и материалы лежат в `plugins/noorules/` и готовы к установке из этого репозитория.
