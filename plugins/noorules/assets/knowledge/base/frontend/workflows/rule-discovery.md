# Rule Discovery

## Purpose

Identify durable instruction candidates from repeated engineering decisions
without turning one-off implementation details into documentation.

## Applies when

Apply when repeated patterns, review feedback or undocumented conventions are
observed during implementation, review or maintenance.

## Does not apply when

Do not document a single incidental example, temporary workaround, product
rule or framework behavior already owned by official documentation.

## Steps

1. Search existing rules, workflows, checklists and task routing.
2. Gather repeated code, task or review evidence.
3. Classify the candidate as shared, stack-specific or project-specific.
4. Prefer extending the current owner over creating another document.
5. Propose wording, placement and links before changing durable instructions.
6. Obtain the required project approval and update indexes after acceptance.

## Checklist

- [ ] Evidence is repeated or explicitly requested.
- [ ] The candidate has one clear owner.
- [ ] Scope and dependencies are explicit.
- [ ] No product detail leaks into shared guidance.
- [ ] Task routing and links stay current.
