# Изменение бэкенда Sovpa

До изменений прочитай CLAUDE.md бэкенда и применимые .claude/rules; [контекст](references/project-context.md) указывает источники. Эти инструкции собраны для демонстрации по текущим правилам репозитория и не заменяют его актуальные файлы.

## Подготовка

Изучи задачу, кейс, код, тесты, конфигурацию, контракты и текущий diff. Для объёмной или связанной задачи собери контекст по затронутым модулям и вызывающим участкам. Обсуди границы, неоднозначности, план и проверки с разработчиком. Не меняй исходный репозиторий, если поручение ограничено анализом или демонстрацией.

## Реализация

Текущий стек — Go/Fiber, PostgreSQL, Redis и приватное S3. Не выбирай его заново и не переносись на сторонний стек.

Сохраняй границы: presentation → application/domain; application → domain; infrastructure реализует порты application; wiring в cmd/api. Domain/application не импортируют presentation/infrastructure. Пройди маршрут route → handler → application/domain → port → adapter.

Различай глобальный User и SummitProfile; профиль мероприятия может существовать без аккаунта, но до привязки не участвует в списках участников, контактах, встречах, чатах и мэтчинге, с исключением представления назначенного спикера в программе — см. актуальный CLAUDE.md.

HTTP-изменение синхронизируй с routes, DTO, статусами, auth, ошибками и OpenAPI. Для SQL меняй исходные запросы и миграции, не generated-файлы. Сохраняй правила владения транзакциями, context.Context и доменными инвариантами из репозитория. Миграции не запускаются процессом автоматически. Новые зависимости согласовываются по правилам проекта.

## Проверка и передача

Для изменения Go предусмотрен make check: gofmt-check, vet, test, build. По области — дополнительные команды verification.md: sqlc, OpenAPI, Compose, миграции только на одноразовой БД при отдельном разрешённом сценарии. Не запускай инфраструктуру или миграции только ради презентации.

Выдай scope, изменения, проверенные команды и фактические результаты; непроведённые проверки отметь. Перед ревью человеком используй актуальный review-changes из доступного набора, если он выбран для проекта. Не выдавай наличие тестовых команд за выполненные проверки. Git-коммит и push не следуют автоматически из разработки.
