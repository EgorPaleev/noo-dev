# Security-чеклист

Не рассказ, а чеклист состояния и того, что проверять при деплое/ревью.

## HTTP-заголовки

`@fastify/helmet` подключён глобально в `main.ts`. Content-Security-Policy сознательно ослаблена (`'unsafe-inline'` для `styleSrc`/`scriptSrc`, `data:` для `imgSrc`) — дефолтная строгая CSP `@fastify/helmet` ломает Swagger UI на `/swagger` (инлайновые скрипты/стили). Если Swagger UI отключается на проде — CSP стоит ужесточить обратно.

## CORS

`origin` в `main.ts` захардкожен на `http://localhost:3000` — рабочее значение только для локальной разработки. **Обязательно поменять на реальный домен фронта при деплое** (уже зафиксировано в `CLAUDE.md`, здесь — как чек-лист-пункт, не забыть при релизе).

## Rate limiting

`ThrottlerGuard` подключён глобально через `APP_GUARD` (`ThrottlerModule.forRoot`) — ничего дополнительно делать не нужно, точечно отключается `@SkipThrottle()`, настраивается `@Throttle()`.

## Секреты

- `.env` в `.gitignore` — реальные секреты в репозиторий не попадают, коммитится только `.env.example`/`docker/.env.example` с примерами значений.
- Ручной чек перед коммитом: не тащить в `git add` файлы, которые выглядят невинно, но могут содержать реальные значения (дампы, локальные конфиги) — см. общее правило проверки `git status`/`git diff` перед коммитом.
- Автоматическое сканирование секретов (gitleaks/trufflehog) в CI сюда сознательно не добавлено — CI-настройка вне рамок этого чек-листа.

## Docker-образ

`docker/containers/npm/Dockerfile` — это dev-контейнер для локальной разработки: код монтируется volume'ом (`./../:/usr/src/app/` в `docker-compose.yml`), команда запуска — `npm install && npm run build && npm run start:prod` при каждом старте, `USER` не задан (контейнер работает от root — это ожидаемо и уже задокументировано в разделе "Команды": `node_modules` создаётся от root). Отдельного production-образа (multi-stage build, non-root `USER`, `COPY` вместо volume) в репозитории нет — hardening (non-root + multi-stage) стоит добавлять вместе с реальным deployment-пайплайном, а не в этот dev-Dockerfile: multi-stage build не совместим с текущим live-mount разработческим воркфлоу, и добавление non-root `USER` сейчас, скорее всего, сломает `npm install` в volume, смонтированный с правами хоста.

## Зависимости

`npm audit` на момент установки `@fastify/helmet` (2026-08-25) показал **32 уязвимости (1 low, 13 moderate, 17 high, 1 critical)** в существующем дереве зависимостей — не связано с самим helmet, это было в проекте до его установки. Разобрать и обновить — отдельная задача (`docker/dctl.sh run npm audit` для деталей), не входит в текущий security-заход. Автоматизация (`npm audit` в CI или Dependabot/Renovate) сюда тоже сознательно не добавлена по той же причине, что и сканирование секретов.
