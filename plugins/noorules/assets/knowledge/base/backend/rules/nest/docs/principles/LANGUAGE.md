# Язык

- **Идентификаторы** (классы, переменные, функции, файлы, ветки, коммиты) — английский.
- **Всё, что видит человек** — русский: сообщения в логах, тексты исключений (`throw new BadRequestException('...')`), сообщения валидации (`class-validator` decorators, `Joi` схемы), описания в Swagger (`@ApiProperty({ description: '...' })`, `DocumentBuilder`).

```ts
// плохо
throw new NotFoundException('Item not found');

// хорошо
throw new NotFoundException('Запись не найдена');
```

```ts
// плохо — нет message, ошибка валидации уйдёт на английском по умолчанию от class-validator
@IsString()
name: string;

// хорошо
@IsString({ message: 'Название должно быть строкой' })
name: string;
```

`message` обязателен на **каждом** `class-validator`-декораторе, включая `@IsNotEmpty`, `@IsOptional` в связке с типом и т.д. — порядок декораторов и полный пример DTO см. в `docs/conventions/NAMING.md`.

## Комментарии

По умолчанию — без комментариев. Имя переменной/функции/класса должно объяснять, что происходит, само по себе.

Комментарий оправдан только тогда, когда объясняет **почему**, а не **что**: неочевидное ограничение внешнего API, обход бага в зависимости, причина, по которой решение выглядит "неправильным", но таким и должно быть.

```ts
// плохо — пересказывает код
// увеличиваем счётчик на 1
counter += 1;

// хорошо — объясняет неочевидную причину
// Yandex GPT возвращает id пачками по 50, поэтому лимит жёстко ограничен
const BATCH_LIMIT = 50;
```

Не пишутся: комментарии-заголовки секций, закомментированный мёртвый код, комментарии со ссылками на задачу/issue/PR (эта информация — в истории git, а не в коде).
