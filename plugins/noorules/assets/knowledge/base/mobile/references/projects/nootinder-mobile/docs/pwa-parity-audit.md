# Соответствие мобильного приложения PWA

Дата первичного аудита: 19.11.2026.

Текущий статус изменений и проверок: [implementation-progress.md](implementation-progress.md). Таблица ниже фиксирует исходный аудит. По последнему запросу ручной выбор темы исключён: приложение следует системной теме. Android dev временно направлен на production API.

Цель: привести Android/iOS к актуальной PWA по визуальной системе, движению и пользовательским сценариям, сохраняя существующее приложение на Kotlin Multiplatform / Compose Multiplatform и общий Go API.

Уточнение объёма от пользователя: дорабатываем дизайн и функциональность только уже существующих мобильных экранов. Новую общую книгу контактов, публичную визитку, общую ленту новостей и отдельные webview-разделы сейчас не добавляем. Визуальное сравнение пользователь выполнит после более крупного объёма изменений; работа по исходникам и автоматические проверки продолжаются без промежуточных согласований каждого экрана.

## Границы и источники

Это аудит исходного кода. Приложения ещё не запущены для визуального сравнения; соответствие на устройствах не подтверждено. Наличие экрана, API-клиента или теста не означает, что сценарий полностью работает.

Таблица ниже описывает исходные расхождения. Прогресс реализации указан в разделе «Ход работ».

- Мобильный проект: текущий репозиторий; правила — [AGENTS.md](../../../../rules/projects/nootinder-mobile/docs/AGENTS.md), архитектура — [architecture.md](architecture.md).
- PWA: `../../sovpa-app/sovpa-app-client` относительно этой папки. Визуальный эталон — `docs/DESIGN-DIRECTION.md`, фактическая реализация — `src/_app/styles/`, `src/shared/ui/`, `src/widgets/`, `src/_pages/`.
- Бэкенд: `../../sovpa-app/nootinder-api`; публичный контракт — `internal/presentation/openapi/openapi.yaml`, поведение дополнительно проверяется по обработчикам и на тестовом окружении.
- Проверка и запуск — [mobile-testing.md](mobile-testing.md).

Ревизии на момент чтения: mobile `c117f8ab`, PWA `42af7e3`, API `81c1fdd`. Это HEAD локальных репозиториев, не подтверждение версий, опубликованных в сторах или на сервере. Перед визуальной приёмкой нужно отдельно сопоставить запущенные версии с исходниками.

PWA обращается к своему Next.js BFF. Например, `/api/me` преобразуется в `/api/profile` Go API, а список участников PWA запрашивается через `/profiles`, но BFF обращается к `/profiles/recommended`. Мобильный Ktor-клиент продолжает работать с Go API напрямую; адреса и DTO BFF нельзя копировать в него буквально.

Мобильная версия PWA — эталон для композиции телефонных экранов. Hover, браузерная установка, cookies/CSRF, iframe и View Transitions требуют подходящих нативных решений. Существующие возможности телефона, например календарь, не удаляются только потому, что их нет в PWA.

## Уже есть в мобилке

- Общий UI для Android/iOS, Navigation3, Koin, Ktor и платформенные реализации.
- Светлая и тёмная базовые палитры с основными цветами PWA.
- Фон созвездия, сегмент-контрол с пружиной, shimmer, кольцо matching, нижние листы.
- Вход звонком с восстановлением незавершённой сессии, refresh и выход.
- Саммиты, профили, программа, участники, встречи, чаты, новости саммита, спикеры, карта и FAQ.
- Кэширование через Room и `CachedRemoteRepository`, realtime-чат, повтор отправки сообщения, push и обработка части ссылок.
- Передача `brandingColor` в `ProvideCurrentSummitSpark` / `ProvideSummitSpark`.

Эти части дорабатываются по месту. Общий архитектурный перенос или замена стека для задачи не нужны.

## Приоритеты

- P0 — возможность собрать и проверить изменения, сквозные сценарии и данные, блокирующие основное использование.
- P1 — общая визуальная система и соответствие основных экранов.
- P2 — дополнительные разделы, подробная настройка движения и платформенная доводка.

Порядок реализации учитывает зависимости: общие компоненты → первый полный сценарий → остальные разделы. Приоритет проблемы не означает, что её нужно исправлять отдельным несвязанным патчем.

Пройти [матрицу проверки](mobile-testing.md) на Android и iOS, включая реальное устройство, обновление существующей установки и сохранение сессии/кэша. Сборки для сторов и публикация выполняются отдельным явно запрошенным действием.

## Приёмка каждой итерации

1. Список изменённых сценариев и известные ограничения.
2. Android debug-сборка и относящиеся к изменению host-тесты; результат с точными командами.
3. Скриншоты обеих тем и короткое видео, если менялось движение, на одинаковых данных с PWA.
4. Пользовательский чек-лист с ожидаемыми результатами; баги привязаны к экрану, данным и сборке.
5. iOS явно отмечается как проверенная или непроверенная. Общий Compose-код не заменяет проверку на iOS.

Первичная проверка остановилась из-за отсутствия Java в PATH. После установки Android Studio доступны JDK `/opt/android-studio-for-platform/jbr` и SDK `/home/netoot/Android/Sdk`; исходные auth-тесты и сборка `devDebug` прошли. iOS остаётся непроверенной: Linux, Xcode отсутствует.
