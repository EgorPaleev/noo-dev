# Предложение по кешу

Статус: обсуждение, не реализовано в текущем проходе.

## Что уже есть

Room хранит данные профилей, саммитов, программы, чатов, новостей и карты. `CachedRemoteRepository` объединяет чтение сохранённых данных с обновлением из API. Карта сохраняет схемы этажей в байтах вместе с точками. Покрытие кешем не означает, что все просмотренные страницы доступны без сети.

В новостях дополнительные страницы возвращаются из `loadMoreNews`, но не сохраняются через `NewsCacheStorage`. Курсор первой страницы хранится в памяти репозитория. Поэтому после перезапуска просмотренная ранее глубокая часть ленты может быть недоступна без интернета.

## Предлагаемый порядок

1. Сохранять просмотренные страницы новостей и метаданные пагинации, не теряя уже загруженные записи при обновлении первой страницы. Сохранять время последнего успешного обновления; при чтении старых данных показывать спокойную подпись с этим временем.
2. Добавить явную загрузку данных саммита заранее: программа, площадка и карты этажей. Показывать прогресс и объём, предусмотреть очистку данных конкретного саммита и ограничение дискового размера. Фото лучше сохранять по мере просмотра с ограничением размера кеша изображений.
3. Проверить покрытие страниц участников, спикеров и чатов и затем расширять их кеш по тому же принципу. Хранить данные раздельно по аккаунту и саммиту; проверить очистку при выходе из аккаунта.

Автоматическое обновление активных экранов после восстановления связи делается отдельно в текущей задаче. Оно не добавляет новые категории сохраняемых данных.

Первым предлагается пункт 1: он закрывает конкретную обнаруженную потерю просмотренных новостей. Затем — подготовка программы и карт к работе без сети. Офлайн-очередь создания встреч и изменений профиля требует отдельного решения о конфликтах и повторах и в это предложение не входит.
