# Как проверять мобильное приложение

Инструкция для сравнения Android/iOS с PWA. Список доработок — [pwa-parity-audit.md](pwa-parity-audit.md). Android devDebug собран через Gradle; запуск интерфейса на устройстве ещё нужно проверить.

## Самый удобный старт: Android Studio и эмулятор

Android Studio основана на IntelliJ Platform, поддерживает Kotlin Multiplatform и содержит Device Manager для создания виртуального Android-телефона. IntelliJ IDEA также поддерживается для KMP; для старта с Android используем Android Studio.

1. Установить Android Studio с поддержкой версии AGP, зафиксированной в `gradle/libs.versions.toml`. Не соглашаться автоматически обновлять Gradle, AGP, Kotlin или Compose в проекте.
2. В мастере настройки установить Android SDK и инструменты, включая Android SDK Platform-Tools и Android Emulator. В SDK Manager установить платформу для `compileSdk` проекта, сейчас API 37.
3. Открыть корневую папку `nootinder-mobile`, содержащую `settings.gradle.kts`, а не только `androidApp`.
4. Дождаться Gradle Sync и загрузки зависимостей. Плагин IDE Kotlin Multiplatform можно установить через Plugins для дополнительных удобств KMP; для сборки и запуска Android через Gradle он не обязателен. Если Marketplace отказывает в установке, продолжить без него. Gradle-плагины Kotlin/Compose в проекте при этом остаются необходимыми и не удаляются.
5. Проверить Gradle JDK в `Settings → Build, Execution, Deployment → Build Tools → Gradle`: выбрать совместимый с текущими Gradle/AGP JDK. JDK IDE и Java в терминале могут настраиваться отдельно.
6. В `Tools → Device Manager` создать виртуальный телефон, например Pixel. Выбрать образ Android с Google APIs/Google Play для проверки интеграций Google. Образ скачивается через мастер; размер SDK и размер образа — разные вещи. Минимальная версия приложения сейчас Android API 24.
7. Запустить виртуальное устройство. В Build Variants выбрать `devDebug` для `androidApp`, затем конфигурацию Android-приложения и Run.
8. После изменения кода нажать Run снова: IDE пересоберёт и установит приложение на эмулятор. Экран эмулятора можно держать рядом с кодом; окно Running Devices доступно из меню View → Tool Windows.

Для визуального сравнения открыть PWA в Chrome того же эмулятора. Использовать одинаковую тему, аккаунт и саммит. Сначала сравнивать содержимое рабочей области: браузерные панели и системные отступы могут отличаться.

Если конфигурация запуска не появилась автоматически: после успешного Gradle Sync открыть `Run → Edit Configurations → + → Android App`, выбрать модуль `androidApp` и запуск Default Activity. Затем выбрать эмулятор и Run. Альтернатива — собрать APK через `:androidApp:assembleDevDebug` и установить его на эмулятор; команды приведены ниже. Недоступность Marketplace и ошибка загрузки Gradle-зависимостей — отдельные проблемы: вторую диагностировать по конкретному сообщению Gradle Sync.

Вход звонком на эмуляторе: можно ввести свой реальный номер и позвонить на выданный сервисом номер с физического телефона с этой SIM. Эмулятор с приложением должен оставаться в сети и дождаться подтверждения от API. Сам эмулятор не заменяет SIM/реальную телефонию. Этот сценарий надо подтвердить на выбранном тестовом сервере; обход авторизации не добавляется.

Официальные инструкции: [KMP: поддерживаемые IDE](https://kotlinlang.org/docs/multiplatform/recommended-ides.html), [настройка KMP](https://kotlinlang.org/docs/multiplatform/multiplatform-setup.html), [Device Manager](https://developer.android.com/studio/run/managing-avds).

## Какой сервер используется

| Запуск | API по текущему коду | Примечание |
| --- | --- | --- |
| Android `devDebug` | `https://api.sovpa.ru` | Временно подключён production API по запросу; изменения профиля сохраняются в настоящем аккаунте. |
| Android `prodDebug` | `https://api.sovpa.ru` | Работает с production-данными; выбирать осознанно для конкретной проверки. |
| iOS через текущий `initKoinIos()` | `https://api-dev-nootinder.noodev.ru` | Сейчас используется общий URL по умолчанию; Android flavor на iOS не влияет. |
| PWA | Значение `SOVPA_API_URL` на её сервере | Проверить фактическую настройку окружения, не определять её по внешнему URL PWA. |

Для сравнения сначала зафиксировать один API, тестовый аккаунт и саммит. Разные данные dev/prod нельзя принимать за ошибку интерфейса. Поднимать локальный бэкенд необязательно, если выбранный тестовый API доступен.

Оба Android flavor сейчас используют `applicationId = ru.sovpa` без суффикса. Их нельзя установить рядом друг с другом как разные приложения. Debug-подпись также может не совпасть с подписью приложения из стора: при конфликте установки использовать эмулятор/тестовое устройство. Не удалять рабочую установку автоматически ради теста.

## Запуск из терминала

Из корня репозитория, после настройки JDK и Android SDK:

```bash
java -version
./gradlew --version
./gradlew :features:feature-auth-impl:testAndroidHostTest --console=plain
./gradlew :androidApp:assembleDevDebug --console=plain
```

Ожидаемый APK после успешной сборки:

```text
androidApp/build/outputs/apk/dev/debug/androidApp-dev-debug.apk
```

Запуск на уже включённом эмуляторе/подключённом телефоне:

```bash
adb devices
./gradlew :androidApp:installDevDebug --console=plain
adb shell monkey -p ru.sovpa -c android.intent.category.LAUNCHER 1
```

Если подключено несколько устройств, выбрать нужное в IDE или явно настроить целевое устройство для команды. Не запускать установку на случайный телефон.

Для обычной проверки не нужны ключи релизной подписи и сборки для сторов. Не запускать `clean` или полный `build` для каждой правки.

После установки Android Studio исходная сборка и auth-тесты прошли. В текущем Linux Java по-прежнему не добавлена в PATH, поэтому для Gradle используются `JAVA_HOME=/opt/android-studio-for-platform/jbr` и `ANDROID_HOME=/home/netoot/Android/Sdk` перед командой. SDK также можно указать через локальный `local.properties`; этот файл не коммитить. Прогресс и новые проверки — [implementation-progress.md](implementation-progress.md).

## Что проверять на эмуляторе и телефоне

| Где | Для чего подходит |
| --- | --- |
| Android-эмулятор | Композиция экранов, светлая/тёмная темы, переходы, поиск/фильтры/страницы, состояния данных, клавиатура, Back, разные размеры и крупный шрифт. |
| Настоящий Android | Дополнительно реальный звонок, камера/QR, push в фоне, системные разрешения, share, календарь, поведение после сворачивания и плавность на устройстве. |
| iOS Simulator на Mac | Отдельная проверка сборки, safe area, клавиатуры, навигации и интерфейса iOS. |
| Настоящий iPhone | Push, камера/QR, звонок, разрешения, Universal Links, фон и производительность. |

## Минимальная проверка первой готовой итерации

Это чек-лист приёмки целевого поведения; сейчас отдельные пункты ещё требуют реализации, см. аудит.

1. Открыть PWA и debug-приложение на одинаковом API и данных. Записать дату сборки или revision, устройство, Android и тему.
2. На входе проверить логотип, тексты, поле телефона, основную кнопку и условия. Открыть клавиатуру: форма и действие должны оставаться доступны.
3. Ввести неправильный номер: понятная ошибка, повтор работает. Ввести правильный: открывается шаг звонка.
4. Проверить копирование номера, изменение своего номера и возврат назад. Позвонить с нужной SIM; приложение должно продолжить вход после подтверждения.
5. Открыть «Мои саммиты»: пустое состояние или список, приглашение, действующий/предстоящий/завершённый саммит.
6. Открыть действующий саммит: правильный логотип/цвет, видимые разделы соответствуют его настройкам.
7. Открыть конкретное ближайшее событие: должна открыться именно его карточка. Вернуться назад без потери контекста.
8. Повторить визуальные проверки в другой теме. Тема приложения автоматически следует системной; ручной переключатель убран.
9. Выключить сеть: уже загруженные данные и ошибка должны отображаться предсказуемо, без вечного skeleton. Вернуть сеть и повторить загрузку.
10. Свернуть/открыть и перезапустить приложение: сессия и выбранный саммит восстанавливаются в предусмотренный экран. Проверить выход из саммита отдельно от выхода из аккаунта.

## Матрица дальнейшей приёмки

| Раздел | Основной сценарий | Граничная проверка |
| --- | --- | --- |
| Профиль | Имя, email, телефон и аватар сохраняются и видны после перезапуска. | Ошибка, отмена, невалидный ввод, несохранённые изменения. |
| Существующие контакты саммита и QR | Добавить участника в контакты саммита, открыть его профиль, открыть свой QR-бейдж. | Пустой список, повторное добавление/удаление, ссылка до входа. Новые общая книга и публичная визитка исключены из текущей задачи. |
| Участники | Поиск/фильтр/страницы → профиль → назад в прежнее состояние. | Более 100 участников, отсутствующий процент matching, пустой фильтр. |
| Программа | День/тип/избранное → сессия → запись/отмена. | Полная вместимость, изменение занятости другим пользователем, разные часовые пояса. |
| Спикеры | Тема/поиск/страницы → профиль → доклад. | Тема без результатов, длинное имя/компания, возврат к прежнему списку. |
| Встречи | Создать → второй аккаунт принимает/отклоняет → статус обновляется. | Занятый слот, прошедшее время, лимит после отказов, ошибка сервера, место без данных. |
| Чаты | Два аккаунта, отправка, прочтение, бейдж, ответ. | Обрыв сети, повтор без дубликатов, длинный текст, фон/push и восстановление соединения. |
| Карта | Этаж/поиск/точка, pinch/pan/zoom, переход из сессии. | Схемы разных пропорций, нет схемы/точек, стабильный размер пинов. |
| FAQ | Поиск, раскрытие, подгрузка и переход по ссылке. | Нет результатов, длинный ответ, неизвестный ID. |
| Общие состояния | Загрузка/ошибка/пусто/повтор, Back, сохранение состояния. | Крупный шрифт, маленький экран, выключенные анимации, смена саммита. |

Для встреч и чатов нужны два тестовых аккаунта. Для проверки списков — данные, выходящие за первую страницу. Не считать пустой тестовый саммит достаточным подтверждением работы фильтров и пагинации.

## Как сообщать о расхождении

Прислать скриншот, а для движения — короткую запись экрана, и текст:

```text
Сборка / revision:
Устройство и ОС:
API: dev / prod / другое
Экран и саммит:
Тема:
Шаги:
Ожидалось:
Получилось:
Повторяется после перезапуска: да / нет
```

Не присылать access/refresh-токены, приватные ключи или полные логи с персональными данными. Для визуального бага полезны два кадра с одинаковыми данными: PWA и мобилка.

## iOS

На Mac с Xcode и настроенными инструментами открыть `iosApp/iosApp.xcodeproj`, выбрать схему и симулятор, собрать и запустить. Используется общий Compose UI, но платформенные интеграции и поведение проверяются отдельно.

Дополнительные команды из корня на Mac:

```bash
./gradlew :shared:compileKotlinIosSimulatorArm64 --console=plain
./gradlew :shared:iosSimulatorArm64Test --console=plain
```

На текущем Linux iOS остаётся непроверенной. Распространение сборок через TestFlight/сторы выполняется отдельным шагом после локальной проверки и настройки подписи.

## Проверка последнего прохода

1. В профиле приложения проверить положение карандаша ФИО, изменение имени/email и зелёное подтверждение копирования.
2. Открыть историю: лист снизу, закрытие крестиком/жестом, статусы и страницы при более чем шести саммитах.
3. На «Моих саммитах» проверить отсутствие аватара сверху, фото в нижнем меню, дни текущего мероприятия и отсчёт предстоящего.
4. На главной саммита пролистать сессии и встречи; проверить реальные счётчики, переход в программу и меню аватара.
5. В профиле саммита изменить по очереди данные участника, компанию, теги, описание и контакты. После каждой правки остальные поля должны сохраниться. Проверить очистку описания и повторный вход.
6. Открыть QR и настройки: закрытие листов, сохранение публичности и локальных переключателей после перезапуска.
7. Повторить в светлой/тёмной системной теме и с крупным шрифтом.

### Исправления по скриншотам

- В тёмной теме проверить контраст меню аватара, плашку новостей в чатах и подложки иконок разделов; в светлой теме повторить.
- В профиле саммита нажатие на фото/имя открывает основной профиль; редактор должности/компании не должен менять ФИО, телефон или email. Длинное «О себе» раскрывается по кнопке.
- Участники: фильтр должности, поиск, страницы, переключение «Контакты» и повтор загрузки после ошибки.
- Спикеры: фильтр темы доклада, поиск, страницы и сброс «Все».
- Программа: типы мероприятий из API, фильтр в обеих вкладках; процент мэтча открывает нижний лист с объяснением. Закрыть во время загрузки и открыть другую сессию.
- Карта: «Как добраться», адрес с кириллицей и переход в навигатор.

### Меню, телефон, участники и карта

1. На главной саммита открыть меню аватара: фото/инициалы, имя, телефон, иконки, разделители и закруглённая рамка. Проверить длинное имя, оба профиля и выход из саммита.
2. В основном профиле проверить горизонтальные три точки и закруглённую кнопку удаления. Для визуальной проверки достаточно открыть и отменить подтверждение.
3. Смена номера: указать другой номер, получить номер для звонка, скопировать его (зелёное подтверждение), позвонить с нового номера и вернуться. Ожидаются закрытие листа и новый телефон в профиле. Проверить истечение времени, повтор, изменение номера и закрытие во время ожидания. SMS-код не запрашивается.
4. В сессии/воркшопе открыть участников: загрузка, пустое состояние, список, «Показать ещё» и профиль участника. Вернуться в исходную сессию.
5. Нажать место сессии: карта должна открыть соответствующий зал и этаж. Затем «Как добраться до площадки» → адрес → навигатор.
6. В поиске участников, спикеров, программы, чатов и на карте проверить ввод, очистку, клавиатурный поиск и возврат на экран. Для серверных списков результат меняется после небольшой задержки.
7. На карте проверить отдельные чипы этажей, их прокрутку, увеличение двумя пальцами около разных точек и кнопками +/−. При уменьшении схема возвращается к исходным границам, при перемещении не уходит за край.
8. На Android с жестовой навигацией и на iPhone выполнить несколько переходов вперёд/назад, отменить жест возврата в середине. Предыдущий экран не должен рисоваться поверх текущего. Повторить со светлой/тёмной темой и открытой клавиатурой.

Пункты о реальном звонке, навигаторе и жестах требуют проверки на устройстве; host-тесты не подтверждают их работу в операционной системе.

### Общие листы, поиск, анимации и восстановление связи

- В профиле проверить компактный пункт удаления без красной подложки, выбор фото, индикатор загрузки и удаление фото.
- Проверить подтверждения выхода/удаления/отмены: лист снизу, заголовок слева, крестик, основная кнопка над отменой. Выборы компании/должности/тегов, параметров встречи и нового диалога также открываются снизу.
- В участниках и программе проверить уменьшенные промежутки после фильтров. В каждом поиске открыть клавиатуру и нажать вне поля: клавиатура скрывается, а нажатая кнопка/карточка продолжает работать. Повторить в нижнем листе и с очисткой поиска.
- Новости: короткое пояснение под заголовком, текст без обрезки, акцентная полоса только у новых записей, светлая/тёмная системная тема.
- Переходы между экранами: короткое плавное появление без просвечивания старого экрана поверх нового. Карта при открытии зала и при +/− приближается плавно; ручной жест прерывает анимацию.
- Отключить и Wi-Fi, и мобильную передачу данных. На каждом экране ожидается одинаковое янтарное уведомление «Нет интернета». Само подключение к Wi-Fi без доступа в интернет на Android не считается восстановлением.
- Включить сеть: уведомление о потере связи исчезает, появляется зелёное подтверждение, активный экран обновляет данные без ручного повтора. Проверить программу с выбранным днём/фильтром, участников с поиском и чат с набранным, но не отправленным текстом.
- Потерять и восстановить сеть при приложении в фоне, затем вернуться. Проверить переключение Wi-Fi ↔ мобильная сеть и несколько циклов отключения. Формы не должны отправляться автоматически.

Системные события подключения, клавиатура, жесты и внешние окна выбора фото требуют проверки на Android и iOS. На Linux подтверждены только Android-сборка и host-тесты. Изменения хранения кеша описаны отдельно в `cache-improvement-proposal.md` и пока не реализованы.

### Последний проход: профиль и справочники

1. Несколько раз переключиться между «Моими саммитами» и профилем. Проверить первый вход, возврат и прокрутку до нижних секций. Профиль не должен дёргаться от повторного полного обновления при первом показе.
2. Из текущего саммита в профиле перейти на его главную: промежуточная страница входа не показывается. При нескольких текущих саммитах проверить каждый: заголовок, данные и оформление должны относиться к выбранному мероприятию.
3. В профиле саммита открыть должность/компанию: компания сверху, поиск и должности ниже. Выбрать другую должность, снять выбор повторным нажатием, сохранить и открыть повторно. Отмена не должна отправлять изменение.
4. Для сферы, запросов и компетенций проверить поиск, выбранные пункты сверху при открытии, отсутствие перестановок после выбора, счётчик и ограничение восьми вариантов. При восьми вариантах можно снять выбранный, затем добавить другой.
5. Проверить плавное появление вперёд/назад в профиле, программе, участниках, новостях, карте, встречах и настройках; повторить с системным уменьшением анимаций.
6. Отключить сеть. Внизу над меню ожидается общая плашка с действием «Обновить», без дублирующих кнопок на странице. Нажать обновление, затем включить сеть: активная страница должна повторить загрузку. В открытой модалке проверить доступность кнопки обновления того же вида.

### Загрузка списков и FAQ

- На медленной сети открыть участников, спикеров и встречи. Фильтры/вкладки и поиск должны оставаться на своих местах; меняется область результатов, без повторного появления всей панели управления.
- Переключить вкладки встреч и фильтры программы несколько раз. Проверить плавную смену списка, сохранение выбранного пункта и отсутствие повторного запроса при нажатии активной вкладки.
- Открыть программу на дне с текущей сессией: список сразу стоит около неё, без дополнительной прокрутки во время появления экрана.
- Успешно открыть профиль, программу и FAQ, затем потерять сеть и обновить: показанные данные сохраняются. Если данных ещё не было, показывается единая ошибка по центру.
- FAQ: без сети при первом открытии ожидается ошибка загрузки, а не «Ничего не нашли». С сетью ввести запрос без совпадений: это отдельное пустое состояние. Повторить потерю связи после успешной загрузки вопросов.
- Проверить ошибки загрузки карты, новостей, списков и профилей: единая иконка и понятное пояснение по центру доступной области. Поля формы и ошибки сохранения проверяются отдельно от ошибок чтения страницы.
- Плашка без интернета: на страницах без нижнего меню она находится у нижней безопасной области устройства; с меню — непосредственно над ним. В ней только иконка обновления, без надписи на кнопке. Повторить с жестовой/трёхкнопочной навигацией Android, в горизонтальном положении и при открытии клавиатуры; на iOS — с домашним индикатором.
