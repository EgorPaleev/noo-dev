# Продуктовые прототипы

Доведи запрос до артефакта, который можно открыть и проверить. Подбирай глубину реализации под вопрос итерации: один экран, сравнение вариантов, кликабельный сценарий или демонстрация продукта. Для запроса только на ревью верни выводы по существующему прототипу.

## Определи задачу итерации

- Найди ТЗ, референсы, существующий прототип и его точку входа. Определи для каждой запрошенной платформы роль пользователя, исходное состояние, основное действие, видимый результат и путь назад или выход, если он нужен.
- Уточни формат из контекста: макет, браузерная симуляция приложения или запуск на целевой платформе. Если выбор обратим и реальное устройство не нужно для проверки, используй доступный формат и укажи его при сдаче. Задавай вопрос, когда без ответа нельзя проверить ключевой сценарий или выбрать между существенно разными результатами.
- Для правки найди соседние экраны, общие компоненты, навигацию и состояния, которые затрагивает изменение. Для нового сценария сначала собери минимальный сквозной маршрут. Детализируй только те части, которые нужны для проверки гипотезы или прямо запрошены.

## Собери сценарий

- Работай в существующем стеке и используй доступные токены, компоненты, ассеты и терминологию продукта. При старте с нуля выбирай самый лёгкий формат, который воспроизводит нужное поведение и подходит для показа.
- Для нового прототипа без заданной дизайн-системы используй профиль Sovpa как базу. При доработке соблюдай стиль текущего продукта, если пользователь не просит применить стиль Sovpa.
- Свяжи экраны и действия, включая возврат и отмену там, где они влияют на сценарий. После сохранения, выбора или ошибки показывай видимый результат. Проверь, что изменение отражается при переходе на связанный экран, если этого требует сценарий.
- Подготовь синтетические данные. Подбирай состояния под задачу: например, пустой результат поиска, ошибка формы, конфликт записи, загрузка или успешное сохранение. Если состояние трудно воспроизвести обычным путём, дай ревьюеру отдельный способ его вызвать. Добавь предсказуемый сброс, если накопленное демо-состояние мешает повторить показ.
- Для SMS, платежей, уведомлений, геолокации и других внешних действий достаточно симуляции, если итерация оценивает UX. Согласуй представление состояния и результат симуляции между экранами. Реальную интеграцию подключай только если она входит в задачу.
- При сравнении вариантов обеспечь отдельные точки входа и одинаковые исходные данные, чтобы можно было пройти один и тот же сценарий во всех вариантах.

## Проверь и передай

Открой фактическую точку входа и пройди изменённый маршрут. Проверь ключевой результат, обратный переход и затронутые альтернативные состояния в доступной среде для каждой целевой платформы. Для правки общих компонентов проверь по одному связанному экрану каждого затронутого типа. Если часть поведения можно проверить только на устройстве или в недоступной среде, укажи конкретный пробел и выполни доступные проверки.

В результате дай точку входа или артефакт, краткий маршрут для ревью, проверенные размеры или платформы и существенные допущения. Скриншоты приложи, если пользователь запросил их или они нужны для сравнения.
