# Прототип Noolink

Этот раздел относится к корню проекта, где есть `index.html`, `case-1-vhod/`, `case-13-admin/`, `css/` и `js/`. Перед правкой проверь текущий экран, ближайший похожий файл и `CLAUDE.md`. Если карта прототипа и проектное описание расходятся, сверяй ссылки и поведение с фактическими файлами.

## Точка входа и оболочки

- Запусти `python3 -m http.server 8000` из корня проекта и открой `http://localhost:8000/index.html`. Для точечной правки дополнительно открой изменённый экран по прямому URL и через связанный сценарий.
- Пользовательские кейсы используют `.stage > .phone-frame`; в кейсе 13 используется `.desktop-frame` и `css/admin.css`. Десктопный кейс проверяй в поддерживаемом диапазоне ширин. Для превращения админки в мобильную нужен соответствующий запрос.
- Новый экран положи в каталог нужного кейса, добавь `.screen-card` в корневой `index.html` и свяжи его со смежными экранами. Сохраняй рабочие относительные ссылки и существующее соглашение о нумерации файлов.
- Бери токены из `css/tokens.css`, компоненты из `css/components.css`, анимации из `css/animations.css`, общие обработчики из `js/shared.js`. Для админки `css/admin.css` подключается после общих стилей. Размещай модалки, шторки и тосты внутри соответствующей рамки, а `.home-nav` и `.demo-panel` снаружи. На новом экране сохрани характерную для кейса тему и русскоязычные тексты.

## Навигация и состояние

- Для межэкранных переходов используй обычные ссылки, `navigateTo()` и существующие URL-параметры. На экранах внутри саммита переиспользуй `getActiveSummit()` и `applyActiveSummit()`, если экран зависит от темы, брендинга или выбранного саммита.
- Храни изменяемые демо-данные в существующих `*-data.js` и `sessionStorage` под ключами `noolink_*`. Для флагов подходят существующие наборы идентификаторов, для редактируемых записей — массивы. Сохраняй начальные данные, повторное открытие в той же вкладке и сброс через функции кейса. Для новых полей учитывай записи, созданные ранее в той же демо-сессии.
- Для админки переиспользуй `case-13-admin/admin-data.js` и активный саммит. При добавлении ресурса со своим состоянием отрази его в `resetAllAdminData()`. Если мобильный сценарий и админка используют разные источники данных, проверь фактическую связь, прежде чем заявлять синхронизацию.
- При добавлении экрана используй существующую демо-панель и `initDemoPanel()`, чтобы показать значимые альтернативные состояния. Сохранённые, пустые и ошибочные состояния проверяй через основной интерфейс, если у них есть обычный путь воспроизведения.

## Проверка изменений

Для межкейсового перехода пройди оба экрана, например из программы в карту с выбранной точкой. Для мобильных сценариев проверь узкий viewport и длинные русские подписи. Для изменений в общих CSS или JS открой затронутые мобильные экраны и представитель админки. Для редактирования записей проверь повторное открытие в той же вкладке и последующий сброс демо-данных.
