# Шпаргалка: Тим/Тех лид

---

## Оценка задач

- [ ] Определить тип задачи — доработка или новый функционал
- [ ] Доработка → идти в код, оценить по месту реализации
- [ ] Новый функционал → оценить по опыту, при необходимости привлечь лидов вне проекта (через менеджера)
- [ ] Дать оценку раздельно: реализация + сопутствующие работы + риск (×1.2-1.3)
- [ ] Написать итоговое время в чат задачи, тегнуть менеджера
- [ ] Трекнуть время на саму оценку: >15 мин → отдельная задача, <15 мин → в оцениваемую

---

## Работа разработчика с задачей

- [ ] Следить за актуальностью веток в команде
- [ ] При конфликтах — помочь разработчику разрешить локально
- [ ] Контролировать качество коммитов (императивная форма, правильный тип)
- [ ] При необходимости — помочь с архитектурным решением в процессе разработки

---

## Код-ревью

- [ ] Руководить процессом ревью на проекте
- [ ] Проверить соответствие логики кода задаче
- [ ] Предложить более простое решение если видишь
- [ ] Указать на синтаксические и архитектурные ошибки
- [ ] Если много итераций — инициировать созвон вместо переписки
- [ ] Поставить approve когда код готов к мержу
- [ ] Следить что минимальное число апрувов набрано перед мержем

---

## Тестирование

- [ ] При необходимости — помочь QA разобраться в сложном функционале
- [ ] Согласовать чек-лист/тест-кейсы для сложных задач до начала тестирования

---

## Работа с багами

- [ ] Участвовать в оценке критичности бага
- [ ] Для блокирующих багов — помочь найти решение оперативно
- [ ] Контролировать качество фикса (архитектура, не только симптом)

---

## Работа со стендами

- [ ] Отвечать за инфраструктуру стендов совместно с DevOps
- [ ] При инциденте — разбираться первым, подключать разработчика если проблема в приложении
- [ ] Контролировать что деплои идут через правильный процесс

---

## Релиз

- [ ] Участвовать в финальном тестировании и выкатке
- [ ] При неудачном релизе — участвовать во встрече по разбору причин
- [ ] При необходимости — помочь с hotfix

---

## Коммуникации с клиентом

- [ ] При техническом разговоре с клиентом — выступать как единый представитель направления
- [ ] Готовиться к встречам с клиентом заранее — знать статус задач по своему направлению
