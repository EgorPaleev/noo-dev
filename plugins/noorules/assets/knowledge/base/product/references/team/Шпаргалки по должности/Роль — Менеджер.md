# Шпаргалка: Менеджер

---

## Настройка проекта в Битрикс (разово)

- [ ] Создать проект в Битрикс
- [ ] Добавить стадии: Бэклог → Новая/Оценка → Взять в работу → В работе → Готово к тестированию → Тестирование → На доработке → Приёмка → Готова к релизу → Завершена + Регулярные задачи
- [ ] Создать теги ролей под каждое направление на проекте (`мобилка`, `бэк`, `фронт`, `qa`, `аналитик`, `девопс`)
- [ ] Создать регулярную задачу «Коммуникации», «Багфикс» и т.д. (вручную или через робота по необходимости)

---

## Ведение задач

- [ ] Создать задачу в Битрикс: конкретное название, описание/ТЗ (текст, ссылка, чек-лист)
- [ ] Если задача из внешней CRM — скопировать название из источника
- [ ] Поставить тег направления
- [ ] После оценки разработчика — выставить плановое время в Битрикс
- [ ] Рассчитать календарный срок (6ч = 1 день, 7ч = 2 дня)
- [ ] Назначить исполнителя, проставить тег ФИО
- [ ] Перевести задачу в «Взять в работу»

---

## Жизненный цикл задачи

- [ ] Бэклог → оформить задачу → перевести в «Новая/Оценка»
- [ ] После оценки → выставить параметры → перевести в «Взять в работу»
- [ ] Следить за сроками — если разработчик сообщил о сдвиге, пересогласовать
- [ ] После приёмки клиентом → перевести в «Готова к релизу»
- [ ] После релиза → перевести в «Завершена»

---

## Оценка задач

- [ ] Получить оценку от разработчика в чате задачи
- [ ] Выставить плановое время в поле Битрикс
- [ ] Рассчитать и выставить календарные сроки
- [ ] Если оценка расходится с реальностью — организовать созвон с командой

---

## Работа с багами

- [ ] Если баг пришёл от клиента — уточнить: это баг (не соответствует ТЗ) или новая задача?
- [ ] Если баг — передать QA для воспроизведения
- [ ] Если новая задача — создать в бэклоге и запустить жизненный цикл
- [ ] Оценить критичность совместно с командой, зафиксировать в чате задачи

---

## Приёмка задачи

- [ ] Показать результат клиенту (стенд, демо, видео — по договорённости)
- [ ] Дождаться «ок» от клиента
- [ ] Закрыть задачу в Битрикс — это сигнал для команды
- [ ] Если есть нюансы — зафиксировать их в задаче при закрытии
- [ ] Если замечания — вернуть задачу в «На доработке»

---

## Релиз

- [ ] За 3-5 дней — собрать список задач на стадии «Готова к релизу»
- [ ] Создать релизную задачу со ссылками на все задачи в релизе
- [ ] Объявить фриз стенда — зафиксировать версии компонентов
- [ ] Подтвердить готовность к выкатке — синхронизировать участников
- [ ] После релиза — зафиксировать итоги в релизной задаче
- [ ] Если релиз неудачный — принять решение об откате или hotfix, организовать встречу (~30 мин)

---

## Коммуникации внутри команды

- [ ] Организовывать дейлики 1-3 раза в неделю, создавать задачу под каждый дейлик
---

## Коммуникации с клиентом

- [ ] Быть основной точкой контакта с клиентом
- [ ] При необходимости технического разговора — подключить одного представителя направления
- [ ] Участвовать в плановых статус-созвонах с клиентом
- [ ] Фиксировать итоги коммуникации в задаче или чате
