# Шпаргалка: Разработчик

---

## Оценка задач

- [ ] Получил задачу на оценку — идти в код (доработка) или оценить по опыту (новый функционал)
- [ ] Если не можешь оценить — обратиться к тим/тех лиду или старшему разработчику
- [ ] Дать оценку раздельно: реализация + сопутствующие работы + риск (×1.2-1.3)
- [ ] Написать итоговое время в чат задачи, тегнуть менеджера
- [ ] Трекнуть время на оценку: >15 мин → отдельная задача, <15 мин → в оцениваемую задачу

---

## Работа с задачей

- [ ] Прочитать ТЗ, задать вопросы если нужно — зафиксировать ответы в чате задачи
- [ ] Обновить `dev` перед созданием ветки:
  ```
  git checkout dev
  git pull origin dev
  git checkout -b feature/bitrix-task-{номер}
  ```
- [ ] Перевести задачу в «В работе»
- [ ] Реализовать задачу, коммитить в императивной форме (`feat:`, `fix:`, `refactor:`, `chore:`)
- [ ] Один коммит если задача в рамках дня, несколько — если многодневная
- [ ] Каждый раз возвращаясь к ветке — актуализировать относительно `dev`:
  ```
  git fetch origin
  git rebase origin/dev
  ```
- [ ] Если возник блокер — написать в чат задачи, при срочности — Telegram или ЛС менеджеру
- [ ] Если сроки сдвигаются — сообщить в чат задачи заранее с объяснением причины

---

## Создание MR и передача на тестирование

- [ ] Создать MR в GitLab: `feature/bitrix-task-{номер}` → `dev`
- [ ] Название MR = название задачи в Битрикс
- [ ] Описание: кратко что сделано, нюансы если есть
- [ ] Проставить ревьюера
- [ ] Ссылку на MR положить в чат задачи
- [ ] Опционально: добавить комментарий и ссылку на APK/диск
- [ ] Перевести задачу в «Готово к тестированию»

---

## Код-ревью

- [ ] Участвовать в ревью других разработчиков
- [ ] Проверить логику кода, предложить упрощение если видишь
- [ ] Оставить комментарии в MR, поставить approve когда всё ок
- [ ] Если много итераций — предложить созвон

---

## Доработка после тестирования

- [ ] Получил задачу в «На доработке» — вернуться в ту же ветку
- [ ] Актуализировать ветку:
  ```
  git fetch origin
  git rebase origin/dev
  ```
- [ ] Исправить баг, коммит в формате `fix: ...`
- [ ] Запушить в тот же MR — новую ветку не создавать
- [ ] Перевести задачу в «Готово к тестированию»

---

## После приёмки

- [ ] Задача прошла приёмку → замержить MR
- [ ] Удалить ветку локально (на GitLab оставить)

---

## Работа с багами

- [ ] Баг ≤30 минут → трекать время в задачу «Багфикс»
- [ ] Баг >30 минут → создать отдельную задачу, оценить и запустить жизненный цикл
- [ ] Фиксировать баг в той же ветке и том же MR если задача ещё не замержена

---

## Работа со стендами

- [ ] При падении стенда — сообщить в чат
- [ ] Подключиться к устранению если проблема на уровне приложения

---

## Релиз

- [ ] Участвовать в выкатке по своему направлению
