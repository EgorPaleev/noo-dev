# Состояние запуска

Храни служебное состояние в `.noorules/runs/<id>/run.json`. ID состоит из строчных латинских букв, цифр и дефисов. Одному запуску соответствует один активный исполнитель. Перед обновлением перечитывай состояние и проверяй, что этап ещё не завершён в другом сеансе.

## Где сохранять файлы

- По умолчанию сохраняй согласованный план, результаты этапов, файлы субагентов и итоговые материалы прямо в корне рабочей папки проекта. Используй имя `<id>-plan.md` для плана и `<id>-<имя-результата>.<расширение>` для результата, если пользователь не назначил имя. Если пользователь указал путь или папку для результатов, используй этот путь внутри рабочей папки проекта и за пределами `.noorules/`.
- Перед запуском выбери разные пути для независимых этапов и проверь, что новый результат не перезапишет существующий файл без поручения пользователя. Даже при продолжении старого запуска назначай новые выходные пути вне `.noorules/`. Пути к ранее созданным файлам используй в прежнем виде для чтения и проверок.
- Записывай в `run.json` относительные ссылки на план, результаты и файлы, от которых они зависят. Показывай пользователю ссылки на сами результаты.

При создании или ремонте записи используй [схему run.json](../../../assets/knowledge/flow-run.schema.json). Строки отпечатков ниже приведены для примера.

```json
{
  "schemaVersion": 1,
  "pipeline": "review-only",
  "pluginVersion": "0.4.7",
  "plan": {
    "path": "feature-review-plan.md",
    "fingerprint": "git:0123456789abcdef0123456789abcdef01234567"
  },
  "steps": [
    {
      "id": "review",
      "task": "code-review",
      "skill": "noo-review",
      "inputs": ["change-set"],
      "optionalInputs": ["verification-report"],
      "output": "review-report",
      "status": "completed",
      "usedInputs": {
        "change-set": {"path": "work/changes.diff", "fingerprint": "git:0123456789abcdef0123456789abcdef01234567"}
      },
      "result": {
        "path": "feature-review-review-report.md",
        "fingerprint": "git:abcdef0123456789abcdef0123456789abcdef01"
      }
    }
  ],
  "externalInputs": {
    "change-set": {"path": "work/changes.diff", "fingerprint": "git:0123456789abcdef0123456789abcdef01234567"}
  }
}
```

- После одобрения укажи путь и отпечаток файла плана в поле `plan`. Запиши этапы со статусом `pending` и их контрактами. Храни обязательные входы в `inputs`, необязательные — в `optionalInputs`. Готовый этап имеет все обязательные входы и завершённые зависимости из `dependsOn`. Для старых запусков сохраняй список `inputs` и прежний порядок готовности. Отсутствующее поле `optionalInputs` означает пустой список.
- Для входа этапа используй результат предшественника, который объявляет нужный артефакт. Если несколько предшественников объявляют одинаковое имя, зафиксируй однозначный источник в плане или используй разные имена для выходов. При отсутствии этапа-источника ищи файл в `externalInputs`. Отсутствующий или изменившийся обязательный вход фиксируй как ожидание. Пропусти недоступный необязательный вход и отметь ограничение, если оно влияет на результат. Для любого фактически использованного входа сохрани отпечаток в `usedInputs`. Независимый этап можно продолжить.
- Записывай путь относительно проекта. Для отпечатка используй `git hash-object --no-filters -- <путь>` либо SHA-256. Укажи метод в поле `fingerprint`. Если автоматическая проверка недоступна, сохрани копию файла и запиши её путь в `snapshotPath`.
- После выполнения навыка запиши файл результата, использованные входы и статус `completed`. Статус без результата не закрывает этап. Уточнение, решение человека или отсутствующий вход фиксируй как `waiting` с причиной.
- В `appliedMaterials.skills` и `appliedMaterials.rules` сохраняй имена фактически применённых навыков и ID или пути правил. В `appliedMaterials.uses` укажи для каждого материала пару `material` и `effect`, которая объясняет конкретное решение или проверку.
- В `model` каждого нового этапа сохраняй `level` и `reason`, а при подтверждённой доступности модели — её ID в `recommended` и настройку `reasoningEffort`. Записывай `used` и `usedReasoningEffort` только по данным среды. Если плановый выбор нельзя применить, укажи `fallbackReason`.
- Если результат ссылается на отдельный diff или файлы результата, запиши их пути и отпечатки в `dependencies` рядом с основным артефактом. Проверяй их при повторном использовании так же, как основной файл.
- При продолжении сначала сверяй версии контрактов оставшихся шагов, затем файлы и их отпечатки. Изменившийся результат и завершённые шаги, которые зависели от него прямо или через другие результаты, помечай `stale` с причиной. Для необязательного артефакта учитывай зависимость завершённого шага, если артефакт записан в `usedInputs`. Неисполненный шаг без обязательного входа получает `waiting`. Независимые этапы сохраняют свои результаты. Прежние файлы сохраняй, обновлённую часть запускай под отдельным ID или используй согласованную версию входа.
- При сравнении сохранённого контракта с текущим считай имена `noorules-<имя>` и `noo-<имя>` одним навыком, если короткое имя совпадает с назначением в действующем сценарии. Для следующего шага открывай навык по текущему имени. Смена префикса сама по себе сохраняет статус и артефакты.
