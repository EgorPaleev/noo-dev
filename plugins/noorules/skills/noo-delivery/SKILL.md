# QA и выпуск

Используй входы нужного этапа. Для `qa` сопоставь критерии, изменения и ревью, проведи доступные функциональные проверки и сохрани `qa-report`. Для `acceptance` зафиксируй фактическое решение ответственного, открытые ограничения и версии артефактов. Если решения ещё нет, запроси его и оставь этап ожидающим.

Для `release` запиши состав, цель, результаты проверок, порядок выпуска, условия остановки и отката по [чек-листу](../../assets/knowledge/base/product/checklists/release-readiness.md). Результат шага — `release-package`; фактическая выкладка и внешний статус следуют из отдельного поручения.
