# Подключение NooRules

Для явного запроса обновить плагин используй [порядок обновления](../noo-task/references/version.md).

1. Найди корень проекта и прочитай действующие инструкции. По задачам, для которых подключают NooRules, проверь исходный код, манифесты, команды запуска и проверок, документацию и принятый порядок работы. В монорепозитории выясни, какие соглашения принадлежат отдельным пакетам. Проверь [загруженный плагин и точку входа](references/project-layout.md#диагностика-подключения).
2. При первом подключении собери карту того, что уже есть и что мешает начать работу. При повторном запуске сверь эту карту с текущими файлами и покажи изменения и оставшиеся пробелы. Для каждого существенного пробела предложи конкретное дополнение с путём и источниками. Подходящие материалы NooRules используй как шаблоны для документации и правил целевого репозитория. Различай наблюдения по коду и соглашения команды. Если решение ещё открыто, оставь вопрос с источником и влиянием.
3. Подключи проект и внеси одобренные дополнения по [схеме проекта](references/project-layout.md). Сохраняй контекст, правила и навыки в целевом репозитории. Переиспользуй канонические документы и добавляй ссылки на подтверждающие исходники. Добавляй зависимости и внешние инструменты только по согласованному поручению. Сохрани уже действующие локальные настройки при повторном подключении.
4. Проверь, что каждый настроенный клиент видит один блок автоматического входа. В итоговом отчёте кратко укажи результат диагностики. На примере одной задачи покажи источник проектного правила, подходящий маршрут и доступную команду проверки. Дай ссылки на изменённые файлы. Если автоматический вход только что добавлен, предложи начать новую сессию в проекте и отправить задачу или ТЗ обычным сообщением.
