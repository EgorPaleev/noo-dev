# Структура проекта

- В `.noorules/project.md` запиши цель подключения, пути к нужной документации и источникам требований, действующие инструкции и способ ведения задач. Указывай только подтверждённые настройки. Используй относительные пути внутри проекта.
- Если команда уже согласовала приоритет выбора модели, запиши его там же. Явное пожелание для текущей задачи имеет приоритет.
- В `.noorules/profile.json` положи `schemaVersion: 1`, `catalogVersion` из [каталога](../../../assets/knowledge/catalog.json), название проекта в `project`, список `presets` и подтверждённый `projectScope`, если он есть. Запиши признаки из файлов проекта в `presetEvidence`, пути инструкций в `localInstructionPaths` и найденные команды в `checks`. Название папки само по себе недостаточно для включения проектного набора.
- Найди точки входа `AGENTS.md` и `CLAUDE.md`. Если одна ссылается на другую, обнови целевой файл. Используй один короткий блок со ссылкой на настройки NooRules и индекс документации в согласованной точке входа.
- При необходимости создай недостающую страницу в `docs/noorules/`. Карта архитектуры нужна, когда этап зависит от модулей и контрактов. Для проверок указывай команды со ссылкой на объявление или инструкцию и с отметкой окружения. Описания продукта и причины решений бери из подтверждённых источников.
- Для ADR используй существующий журнал, а при его создании положи [шаблон](../../../assets/knowledge/base/engineering/templates/adr.md) в `docs/adr/0000-template.md`. Словарь пополняется по мере появления согласованных терминов. Для нескольких доменных областей используй указатель на отдельные словари.
- Локальные дополнения хранятся в `.noorules/local/{rules,skills,workflows,checklists,templates,examples,references}/`. Создавай папки по мере появления материалов. Навык живёт в `skills/<id>/SKILL.md`. В `.noorules/local/tasks.json` ключ — тип задачи, значение — список относительных путей к материалам. Ключ `*` обозначает общие для проекта правила.

## Автоматический вход

При подключении NooRules помести блок в корневую точку входа клиента: `AGENTS.md` для Codex и `CLAUDE.md` для Claude Code. Если инструкции одного клиента уже подхватывают другой файл, используй общий блок при условии, что он доступен обоим клиентам. Создай недостающий корневой файл для подключаемого клиента. При повторной настройке обнови существующий блок. Если в нём уже настроено другое направление, замени точку входа только по явному запросу переключить направление. Сохрани остальные инструкции и ссылки проекта. Автоматический вход применяется к новым сессиям, открытым в проекте с установленным плагином.

```markdown
<!-- noorules:task-entry -->
## NooRules

Если доступен навык NooRules `noo-task`, используй его для рабочих запросов, ТЗ и продолжения согласования в этом чате. Перед планированием и выполнением учитывай действующие инструкции и правила репозитория. При явном вызове рабочего навыка используй его в качестве запрошенного этапа и следуй порядку согласования `noo-task`. Справочные вопросы, настройку, рекомендации и команды управления запуском обрабатывай по назначению запроса.
<!-- /noorules:task-entry -->
```

## Диагностика подключения

Покажи пользователю три строки, используя только подтверждённые сведения.

1. **Плагин.** Определи фактический путь загруженного `noo-setup/SKILL.md` по данным текущей сессии. Прочитай манифест пакета, которому принадлежит этот путь (`.codex-plugin/plugin.json` или `.claude-plugin/plugin.json`). Укажи версию и путь пакета. Если путь или версия недоступны, явно укажи, какое поле не удалось подтвердить. Если в рабочем репозитории лежит исходный пакет того же плагина, покажи его версию отдельно. При расхождении укажи, какая версия действует в сессии и что потребуется загрузить для проверки изменений.
2. **Автоматический вход.** Укажи клиент, корневой файл или загружаемый им общий файл, наличие одного блока для `noo-task` и наличие самого навыка в сессии. Отдельно отметь, если блок только что записан и его подхватит новая сессия. Если точка входа уже относится к другому направлению, покажи это как состояние настройки.
3. **Правила проекта.** Назови используемые проектные инструкции, пресеты и доступные проверки. При повторной настройке сверь их с существующими `.noorules/project.md` и `.noorules/profile.json`. Покажи только изменения и существенные пробелы. Если изменений нет, сообщи об этом и приведи пути к действующим настройкам.
