# Реализация

Сначала [проверь подключение текущего проекта](../noo-rules/references/project-context.md#подключение-проекта). Выполняй этот навык NooRules Dev в подключённом проекте.

Для нового запроса используй [порядок входа рабочего навыка](../noo-rules/references/project-context.md#вызов-рабочего-навыка).

Определи критерий ближайшего законченного изменения. Изучи владельца поведения, применимые инструкции репозитория и ближайшую проверенную реализацию. Выбери подход по фактическому коду, требованиям и результатам проверок. Подбирай дополнительные навыки и проверки, когда они помогают получить согласованный результат. Для специфичной области используй подходящий маршрут, если он есть.

Самостоятельно уточняй способ реализации внутри согласованного объёма по мере изучения кода. Если находка меняет объём, критерии или требует отступить от обязательного правила проекта, объясни влияние и согласуй решение. Проверь поведение и diff. При необходимости используй `noo-test`. В пайплайне сохрани `change-set` с diff или ссылкой на зафиксированный diff, исходной точкой, связью с критериями и фактическими проверками. Укажи значимые новые файлы, которые обычный diff пропускает.
