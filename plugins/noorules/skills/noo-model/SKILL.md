# Подбор модели

1. Определи результат, этап, сложность исходных материалов и последствия ошибки. Возьми приоритет из запроса или из `.noorules/project.md`, если он там записан. Сверь [правило выбора](../../assets/knowledge/base/engineering/rules/model-routing.md).
2. Сначала выбери уровень. Если есть список реально доступных моделей и возможностей, предложи основную и, когда это полезно, резервную. Для нескольких этапов подбирай уровень отдельно.
3. Для пайплайна внеси в общий план отдельный выбор для каждого этапа и короткое обоснование. Простое извлечение, основная реализация и проверка дорогих ошибок могут требовать разных моделей или разной глубины рассуждения. Если пользователь попросил оставить текущую модель для всех этапов, соблюдай это. При неизвестной доступности укажи только требуемый уровень.
4. Для отдельной задачи и существенной смены основной модели предложи «Переключить / Оставить текущую?». В Codex CLI после согласия укажи `/model <id>`, если ID подтверждён, или `/model` для выбора из списка. Дождись следующего сообщения пользователя перед продолжением на новой модели и напомни ожидаемый шаг или ID запуска.
5. Для маршрута `model-selection` подготовь `model-plan` со списком этапов, основанием и условиями повышения уровня. Для исполнения пайплайна передавай выбор при запуске конкретного субагента. Фактически использованную модель указывай по данным среды.
