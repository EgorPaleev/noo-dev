# Подготовка рабочей ветки

Сначала [проверь подключение текущего проекта](../noo-rules/references/project-context.md#подключение-проекта). Выполняй этот навык NooRules Dev в подключённом проекте.

Для нового запроса на подготовку ветки передай его в [`noo-task`](../noo-task/SKILL.md) с маршрутом `working-branch`. Выполняй команды только после [согласования плана](../noo-flow/references/approval.md) и из рабочей копии нужного проекта.

1. При планировании определи имя по правилам проекта и учти указанное пользователем имя. Если установленного формата и заданного имени нет, используй `<тип>/<короткое-описание>` по смыслу задачи, например `feat/autonomous-task-flow`, `fix/error-message`, `docs/setup-guide`, `refactor/router` или `chore/update-tooling`. Для описания по умолчанию используй строчные латинские буквы, цифры и дефисы. Проверь имя через `git check-ref-format --branch` и укажи его в плане. При исполнении используй одобренное имя. Если remote не задан, используй `origin` при наличии или единственный настроенный remote. Если база не задана, скрипт определит основную ветку на сервере. При неоднозначном remote или отсутствии удалённой базы уточни источник.
2. Запусти `sh <путь-к-навыку>/scripts/prepare-branch.sh <рабочая-ветка> <remote> [<базовая-ветка>]`. Скрипт проверяет состояние рабочей копии, запрашивает актуальную базу и создаёт ветку от полученного коммита. При отказе Git или отсутствии доступа к remote этап остаётся в ожидании. При незакоммиченных изменениях в отслеживаемых файлах используй отдельную согласованную рабочую копию или дождись решения пользователя. Сохраняй локальные файлы пользователя и учитывай только изменения этой задачи в её diff.
3. Зафиксируй результат `working-branch` по [правилам состояния](../noo-flow/references/state.md) с корнем рабочей копии (`git rev-parse --show-toplevel`), именем ветки, remote, базовой веткой и SHA базового коммита. Перед каждым этапом этого запуска, в том числе после возобновления, из той же рабочей копии проверь текущую ветку через `git branch --show-current` и наличие базового коммита в её истории через `git merge-base --is-ancestor <SHA-базы> HEAD`. При несовпадении восстанови рабочий контекст по записанному результату с сохранением локальных изменений или приостанови этап. Для продолжения используй ранее созданную ветку и записанную базу.
