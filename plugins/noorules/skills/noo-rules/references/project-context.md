# Правила подключённого проекта

## Подключение проекта

Проверяй подключение к текущему проекту перед любым рабочим запуском, включая явный вызов, продолжение по ID и работу переданного этапа.

- Найди корень текущего проекта. Для Git используй корень текущей рабочей копии. Для папки без Git используй открытый корень проекта. Прочитай корневой файл клиента (`AGENTS.md` для Codex или `CLAUDE.md` для Claude Code). Общий файл учитывай, если корневые инструкции этого клиента его подключают.
- В этих инструкциях должен быть действующий блок `<!-- noorules:dev:task-entry -->` с точкой входа `noo-task`. Подходит также старый `<!-- noorules:task-entry -->`, если он явно подключает этот навык. Упоминание навыка в примере, глобальных инструкциях, соседнем проекте или блок другого направления не подключает текущий проект.
- Если подходящего блока нет или его нельзя проверить, не запускай рабочий маршрут NooRules Dev. Обычный запрос обрабатывай по правилам текущего проекта. При явном вызове коротко укажи, что проект ещё не подключён и для подключения можно явно вызвать `noo-setup`. Самостоятельно настройку не запускай.
- Явный вызов `noo-setup` служит для подключения проекта. Установка пакета делает его команды доступными в клиенте. Активировать рабочий процесс для проекта позволяет настроенный блок.

При первом рабочем запуске после проверки проекта [один раз напомни об обновлении](../../noo-task/references/version.md) и продолжи задачу. Пропусти напоминание при явном запросе на обновление или если в этой сессии уже был совет от setup, напоминание или обновление. На этапах и в субагентах пропускай напоминание.

Прочитай правила этого плагина в `.noorules/dev/rules.md`, если файл есть.

При первом разборе задачи прочитай корневые инструкции, действующие инструкции затронутых каталогов и относящиеся к задаче документы проекта. Если существуют `.noorules/project.md` и `.noorules/profile.json`, используй их как указатели на источники, стек и проверки. Сверяй сведения с текущими файлами. Для каждого маршрута используй локальные материалы из `.noorules/local/tasks.json` по ключам маршрута и `*`.

Соблюдай обязательные требования репозитория в пределах их области действия. Используй рекомендации, примеры и материалы NooRules как опору для самостоятельного решения. Опирайся на код, данные задачи и доступные инструменты. Если правила проекта расходятся и область действия не разрешает конфликт, вынеси решение в план. Если подходящего правила или маршрута нет, продолжай по требованиям задачи и подтверждённым фактам проекта.

В ходе работы собирай подтверждённые сведения, которые пригодятся в следующей задаче. Сохраняй их в канонических документах этого репозитория, когда обновление документации входит в согласованный объём. Ссылайся на источники. Если обнаруженный пробел влияет на работу, предложи конкретную правку и путь для записи. Записывай новое правило команды или зависимость по согласованному поручению.

## Контекст между этапами

Передавай вместе с согласованным планом короткий список уже проверенных источников, применимых требований и команд проверок. В одном чате переиспользуй эти сведения на той же рабочей копии, пока область задачи и источники прежние. Для следующего этапа открывай лишь новые материалы, нужные для его результата, и перечитывай источники, которые изменились.

После подготовки ветки или смены рабочей копии сверь охваченные правилами пути с новой базой. Прочитай изменившиеся и появившиеся инструкции. При расширении задачи прочитай правила новых каталогов. При возобновлении в другом сеансе или передаче субагенту используй сохранённые ссылки как указатели и проверь применимые инструкции в фактической рабочей копии. Соблюдай отдельные проверки рабочей ветки и входов, заданные пайплайном.

## Вызов рабочего навыка

- Если навык выполняет уже одобренную работу из `noo-task` или этап `noo-flow`, используй правила проекта и приступай по переданному контракту.
- Для нового рабочего запроса или явного вызова рабочего навыка в подключённом проекте передай запрос в [`noo-task`](../../noo-task/SKILL.md) вместе с именем вызванного навыка. Если механизма передачи нет, прочитай инструкции `noo-task` и следуй им в текущем ходе. На этапе планирования используй инструкции навыка для определения входов, результата и проверки. Выполняй этап после запуска согласованного пайплайна.
- Для справки, рекомендации или запроса только на план либо спецификацию применяй правила проекта и возвращай запрошенный результат сразу.
