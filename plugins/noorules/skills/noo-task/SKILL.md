# Работа с задачей

Сначала [проверь подключение текущего проекта](../noo-rules/references/project-context.md#подключение-проекта). Выполняй этот навык NooRules Dev в подключённом проекте.

Если координатор передал тебе этап уже согласованного пайплайна, сверь проектные правила и выполни этап по контракту и [правилам для субагента](../noo-flow/references/delegation.md). При отсутствии отдельного навыка-исполнителя действуй по контракту этапа, используя подходящие материалы.

## Вход

- Используй доступные вводные: сообщение, ссылки, логи, примеры, готовый diff и содержимое проекта. Сверь их с ожидаемым результатом. Недостающие сведения отрази в плане с влиянием на работу. Отдельное решение запрашивай там, где без него нельзя подготовить полезный результат по затронутой части.
- Если пользователь отвечает на ожидающее согласование, примени [правила согласования](../noo-flow/references/approval.md). Для отдельного нового запроса сохрани предыдущий план на текущем шаге.
- На справочные вопросы отвечай прямо. Для рекомендаций, настройки, подбора правил и управления запуском используй [навык по результату](../noo-guide/SKILL.md#навыки-по-результату). Если нужен только план или спецификация без реализации, сверь [правила проекта](../noo-rules/references/project-context.md) и верни запрошенный результат.
- Для каждой новой задачи разработки сначала покажи план и пайплайн и дождись подтверждения запуска. Это относится и к правке в одну строку, и к явному вызову навыка реализации. До подтверждения ограничься чтением. Для других рабочих задач с понятным объёмом также предложи план и пайплайн вместе. Учитывай явно запрошенный навык при выборе исполнителя и сверь его входы и результат. Для отдельного ревью готового diff используй `review-only`, где достаточно исходной точки и diff.

## Работа по плану

1. Прочитай задачу или ТЗ, [проектные правила](../noo-rules/references/project-context.md) и относящиеся к запросу файлы. Определи результат, границы и способ проверки. Если открытое решение меняет объём или критерии, уточни это решение и продолжи разбор независимой части. Для остальных задач переходи к подбору пайплайна в этом же ходе.
2. [Подбери пайплайн](../noo-flow/references/composition.md). Поставь [`noo-branch`](../noo-branch/SKILL.md) первым этапом новой разработки. Используй уже прочитанные правила и подбери через `noo-rules` дополнительные материалы по цели этапа и маршруту. Покажи в одном сообщении план, этапы, входы, результаты, проверки и существенные зависимости. Укажи только те правила проекта, которые меняют решение или проверку, со ссылкой на источник и коротким объяснением. Прими правки и обработай запуск по [порядку согласования](../noo-flow/references/approval.md).
3. Передай в [noo-flow](../noo-flow/SKILL.md) согласованные план и пайплайн в их последней версии, включая исходное ТЗ или ссылку на него, проверенные источники и правки пользователя. Если механизма вызова нет, прочитай файл и выполни его инструкции в текущем ходе.

Для [короткого маршрута](../noo-flow/references/composition.md#короткий-маршрут) в том же сообщении предложи дополнительные шаги, которые имеют смысл для задачи, например отдельное ревью, расширенный прогон тестов или подготовку коммита. Если пользователь уже определил состав или проект требует конкретный шаг, сразу отрази это в плане. Если пользователь согласовал запуск без выбора предложенных опций, выполни показанный основной вариант.
