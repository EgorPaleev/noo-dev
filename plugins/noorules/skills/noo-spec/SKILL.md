# Спецификация

Для нового запроса используй [порядок входа рабочего навыка](../noo-rules/references/project-context.md#вызов-рабочего-навыка).

Прочитай согласованный кейс, актуальные ADR и выводы прототипа, если он есть. Сформулируй проблему, границы, пользовательские сценарии и проверяемые критерии. Сопоставь затрагиваемые контракты с кодом. Укажи способ проверки каждого значимого изменения и нужные входные материалы для разработчика.

Для нескольких частей выдай небольшие проверяемые задачи с явно указанными блокирующими зависимостями. Отметь открытые решения в том месте, где они влияют на план. Рабочий результат можно сохранить в проекте. Создание задач в стороннем трекере выполняется при явном поручении.

Если вызов сделан из пайплайна, сохрани спецификацию или план как `implementation-plan` в предложенный файл.
